## 三、使用方法

1. 启动游戏并进入存档
2. Cheat Engine 7.5+ → **Open Process** → 附加到 **ved.exe**
3. `File → Load` 载入 `VED_YC_CheatTable.CT`
4. 勾选 **[★1] / [★2] / [★3]** 即生效（脚本自动搜索特征码并注册符号）
5. 调速：双击 `[数值] 动作速度倍率` 改为 `1.5` 或 `2.0`
6. 微调敌人：把 `[数值] 敌人动作速度` 改为 `0.3`（慢动作）等

**关闭**：取消勾选脚本条目即可自动还原原始字节，无残留。

## 四、技术说明（可移植性）

- **全部使用 AOB 特征码定位 + 代码注入，CT 内不含任何硬编码地址**（已逐项核查：0 处）
- 所有变量/符号由脚本在**运行时动态分配**（16 处 `alloc`），因此**换任何电脑都能用**
- **运行时不依赖 Mono/IL2CPP**（脚本内 0 处 mono 调用），只要 CE ≥ 7.5 且游戏版本一致即可
- 关键注入点：
  - `PlayerController.Update` → 强制 `m_inDefence = 1`（直接锁定格挡状态，而不是和计时器赛跑）
  - `PlayerController → ActionAnimController.m_curPlaySpeed` → 动作速度倍率
  - `EnemyController.Update → EnemyAnimController`：`m_curPlaySpeed` / `m_rmPosFactor` / `m_rmRotFactor` / `m_tempAgentSpeed` 归零 → 定身
  - `WindowEquipShop.CanRefreshShop` → 强制返回 `true`（忽略刷新冷却）

## 九、常见问题（FAQ）

### Q1：为什么每次开游戏，条目里的地址都不一样？需要我手动改吗？

**不需要手动改，这是正常现象，也正是本表能跨电脑使用的原因。**

- 表中的 `[数值] 动作速度倍率`、`[开关] 无限格挡` 等条目，地址栏写的是**符号名**（如 `animSpeedMul`），**不是** `0x7FFB...` 这种写死的地址
- 每次勾选脚本时，CE 会在游戏进程里**当场分配**一块内存给这些符号，所以地址每次不同
- CE 会自动跟着符号解析，你**只管双击改值就行**，完全不用关心它落在哪个地址
- 同理，换到**别人的电脑**上也是自动分配、自动跟随 → 这就是本表不需要针对机器适配的原因

### Q2：为什么我改的数值（比如倍率 2.0）下次开游戏又变回去了？

因为脚本每次启用时会按**脚本里写死的默认值**初始化。v1.0.2 已把动作速度默认设为 **2.0**。
若想改成别的值并永久生效：右键该脚本条目 →「Change script」，把 `animSpeedMul:` 下面的 `dd (float)2.0` 改成你想要的值即可。

### Q3：每次重开游戏都要重新勾选吗？

是的，这是 CE 的正常机制（脚本作用于当前进程）。重开游戏后**勾选一次**即可，脚本会自动重新定位。

### Q4：会不会和别的 CT 冲突？

本表会注册 `pPlayerController` / `pEnemyController` 符号，若其它表也注册同名符号会冲突，**二选一**即可。

## 十、v1.0.1 修复说明（重要）

**问题现象**：勾选 [★2] 敌人定身后再取消勾选，代码虽然还原了，但被写入敌人对象的数值（动画速度=0 等）会**残留**，而游戏自身的状态机因为动画停止而无法自行恢复 → 敌人永久定住。

**修复方案**：脚本在 `[DISABLE]`（取消勾选）阶段会自动：

1. 先还原被修改的原始指令字节（钩子卸载）
2. 再通过**钩子运行时捕获的敌人类型指针**扫描全场，找出所有敌人对象
3. 把 `m_curPlaySpeed`（动画速度）、`m_rmPosFactor` / `m_rmRotFactor`（根运动系数）恢复为 `1.0`，`m_attackAble` 恢复为 `1`

**实测结果**：

```
勾选 [★2] → curPlaySpeed=0.000  rmRot=0.000  atkAble=0     （定身）
取消 [★2] → curPlaySpeed=1.000  rmPos=1.000  rmRot=1.000  atkAble=1   （复活）
```

其余脚本（[★1] / [★3]）取消勾选时只还原代码字节，不留任何数值残留。
