适用：Bloodborne PC 移植版 **bbport**（eboot 1.09，`bb-probe.exe`）。**不适用** PS4 模拟器（shadPS4 等，内存布局不同）。

**版本：v1.7.0**（2026-10-27）　作者：YC

|---|---|---|

## 二、★ 踩坑记录（都是用真机崩溃换来的）

### 1. `obj` 每次启动都会变，只有「槽」稳定
```
槽 0x80553B0E0 → obj    稳定（总指向玩家对象）
obj 本身                每次启动不同（见过 0x1008067310 / 0x10080EC920 / 0x10080EC930）
```
**任何代码都必须每 tick 从槽重读，绝不能缓存 obj。**

### 2. 血量在内存里有三层，只有最上层是权威
| 层 | 例子 | 写它有用吗 |
|---|---|---|
| 显示副本 | `obj+0x154` | ❌ 游戏每帧从上层覆盖 |
| 中间副本 | 状态结构内某处 | ❌ 也被覆盖 |
| **权威值** | 状态结构里的 (当前, 上限) qword | ✅ |
**教训**：只写显示副本会「看起来锁住了，实际照常掉血」。定位权威值要用「写入探针 + 观察显示是否跟随」。

### 3. 体力会自动回复 → 探针法定位必然失败
写「体力-1」再等 60ms 检查，体力早已自己回满，判断永远失败。
**正确做法**：体力真值 = **血量驱动 + `0x3C`**（血量不自动回复，探针有效）。

### 4. 旧锁血失效的真正原因：缓存地址 + 自杀分支
```lua
local obj = getAddressSafe('bb_obj')   -- 启用时缓存一次
if fails > 8 then x.destroy() end      -- 读失败 8 次就自我销毁
```
换图 / 打完 Boss 过场后 obj 重新分配 → 旧地址读到垃圾 → 累计失败 → **计时器自杀**。
这就是社区反馈「打完 Boss 锁血/子弹失效」的根因。
**修复**：每 tick 重读槽 + 去掉所有自杀分支。

### 5. 加载期间 obj 是「占位对象」，绝对不能写
菜单/读盘阶段 `obj+0x158`（血量上限）= 100、当前血 = 0，物品表位置是**未初始化的垃圾**。
此时按「id 匹配就写」会往正在构建的结构里写值 → 破坏加载 → 崩溃。
**防护**：写入前校验 `100 < 血量上限 ≤ 5000` 且 `0 ≤ 当前血 ≤ 上限`，否则整 tick 跳过。

### 6. 全地址空间扫描 = 内存暴涨崩溃
```python
if not hits: hits = scan(0x1000000000, 0x800000000000)   # 126 TB
```
配合每 120ms 一次的重试 → 每秒扫 8 次，实测把游戏内存从 4.8GB 顶到 **9.6GB** 后崩溃。
**修复**：只扫 ±512MB 且重定位加 **5 秒冷却**。

### 7. 写 guest 代码/数据段必须改页保护
那片内存是 `EXECUTE_READ`，直接 `WriteProcessMemory` 返回 0。
**正确顺序**：`VirtualProtectEx(0x40)` → 写 → 恢复原保护。

### 8. 物品表里混了三种东西，只有一种能改
`id_lo` 高位区分类别：
| id_lo 高位 | 含义 | 能否补到 99 |
|---|---|---|
| `0xB000xxxx` | **真物品**（消耗品/材料/弹药） | ✅ |
| `0x8080xxxx`/`0x9080xxxx`/`0xC080xxxx` | 动作、事件、宝箱等**进度标志** | ❌ 改了可能破坏进度 |

### 9. 强化需求改成 0：五条路全部证伪
| # | 候选 | 结果 |
|---|---|---|
| 1 | 168 行升级参数表 `0x1009657EFC` | 全清零后仍扣 260 回响 + 5 碎片 |
| 2 | 40 个浮点需求条目 `0x1008A3xxxx` | 确认框仍显示 ×3 |
| 3 | 18 个浮点条目 `0x1028864xxx` | 同上 |
| 4 | int32 需求值（300+8 / 260+5） | 全进程搜索 0 命中 |
| 5 | 选中武器差分 | 只有瞬态菜单字段 |
**结论**：需求量由 guest 代码现算，宿主侧无权威字段 → **改用材料锁变相实现**。

### 10. 移速倍率：两条路都断了
- 数据层：坐标副本 1.02×、速度读数 1.00×、状态整数无变化、全进程搜不到权威源
- 社区补丁层：摇杆乘数 `0x804927714` 从 1.0 改 2.0，**实测速度无变化**（它只控制起跑阈值）

### 11. 不死模式 + 跳虚空 = 崩溃（已知限制）
不死让你活着掉下去 → 游戏去加载「坠落兜底场景」→ 该资源在本安装缺失 → `guest+0xdab420` 空指针崩溃。
**实测**：关掉不死后跳崖虚空 = 正常死亡、不崩溃。
**所以：要跳崖/掉出地图，请先关闭不死模式。**

### 12. 引擎补丁系统（可复用）
- 换算：`运行地址 = 补丁 XML 的 Address + 0x7FFC00000`（用已生效补丁交叉验证）
- 支持 `bytes` / `bytes32`，**不支持 `byte`**（`debug patch.xml` 因此被引擎跳过）
- 引擎自带 Cheat 菜单的「无限消耗品」描述里明确写了 **Not ... materials** —— 不覆盖强化材料

2. 修改器需与游戏版本匹配，游戏大更新后偏移可能失效

4. 改属性/等级后，开一次状态面板让界面刷新

## 五、v1.7.5：血瓶/子弹「锁不住」与材料补满

### 1 根因：固定行号 ≠ 物品身份

v1.7.0 用两个写死的偏移当血瓶/子弹地址：

```
obj + 0x8B8  -> "子弹"
obj + 0x8E8  -> "血瓶"
```

这其实是**物品表第 1 行、第 4 行的数量字段**。物品表的行序 = **拾取顺序**，实测同一份存档里：

```
r00 id=0x80800056  r01 id=0xB0000384(水银弹)  r02 id=0xB0000078
r03 id=0x80800057  r04 id=0xB00003E8(血瓶)    r05 id=0xB00004CE
```

完全乱序。换个存档、换个拾取顺序，这两个偏移就落到别的物品上——
修改器照样"没报错"，但血瓶/子弹纹丝不动。

### 2 现在的定位方式（四字段特征扫描）

一行物品是 `[id_lo, id_hi, count, flags]`（步长 0x10），判据：

```
id_lo 高 16 位 == 0xB000 且 低 16 位 == 物品号
id_hi 高 16 位 == 0x4000 且 低 16 位 == 物品号
count 在 0..9999
```

先扫标准表（`obj+0x8A0` 起 64 行），扫不到再扫整个 `obj+0x100 .. 0x4000`。
每 tick 用 id 复核缓存，行序变了自动重扫。

### 3 顺带修掉的三处

| 项 | v1.7.0 | v1.7.5 |
|---|---|---|
| 补水周期 | 150 ms（肉眼可见数字跳） | 30 ms |
| 数量上限 | 写死 20 | 开启时读当前值快照，只补不降 |
| 扫描提前退出 | 连续 8 个空行就 break | 逐行独立校验，不再 break |

### 4 血岩 / 血石块：可以「补满」

社区有人反馈血石块锁不住 —— 查下来多数是**背包里根本没有这个材料**。
数量为 0 时物品行会被移除（社区金手指也都注明 "Must Have 1 in inventory"）。

v1.7.5 新增「**补满强化材料**」按钮，一次把 4 种各补到 99：

| 物品 | id_lo |
|---|---|
| 血石碎片 | 0xB0000BB8 |
| 双子血石碎片 | 0xB0000BC2 |
| 血石块 | 0xB0000BCC |
| 血岩 | 0xB0000BD6 |

规则：已有的改数量，没有的写一行新的（需要背包有空位）。
**背包 64 行全满时直接跳过该项，不会去覆盖任何现有物品。**

### 5 实测结论：写进去的材料是持久的

- 写入后背包立刻可见
- 工坊强化 +7→+9（血石块）、+9→+10（血岩）均成功
- **退出游戏重进，材料仍在，武器仍是 +10**

原因：血源是持续自动存档，背包一改就被写进存档。
**所以这跟"锁 99"性质不同——锁是临时的，补材料是改存档。**

### 6 权限提示

若窗口显示「已找到游戏，但打不开进程」：游戏是以管理员身份启动的，
修改器也要右键以管理员身份运行（`OpenProcess` 返回 5 = 拒绝访问）。
